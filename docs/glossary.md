# Glossary

The vowl docs use each word below for one thing only. When a page says
"schema" it means the same thing on every page.

## Contracts and checks

| Term                  | Meaning                                                                                                                                                                                                                            |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Contract**          | A YAML file that follows the [Open Data Contract Standard](https://github.com/bitol-io/open-data-contract-standard). It describes your tables and the checks to run on them. See [Data Quality with Data Contracts](contracts.md). |
| **Schema**            | One entry under `schema` in a contract. It describes one table and has a `name`. Results, adapters and failed rows are all grouped by schema name.                                                                                 |
| **Table**             | The actual table in your database or DataFrame that a schema describes.                                                                                                                                                            |
| **Check**             | One test, such as "price must be positive". Each check has a name, and the check's name is how you find it in every result.                                                                                                        |
| **Generated check**   | A check vowl builds for you from column details such as `logicalType`, `required` or `unique`. See [Auto-generated Checks](contracts.md#auto-generated-checks).                                                                    |
| **Library check**     | A common check you declare with `type: library`, such as `nullValues` or `rowCount`. vowl writes its SQL. See [Library Checks](contracts.md#library-checks).                                                                       |
| **SQL check**         | A check you write yourself with `type: sql` and a `query`.                                                                                                                                                                         |
| **Dimension**         | The group a check belongs to, set with `dimension:`, such as `completeness`, `conformity` or `uniqueness`.                                                                                                                         |
| **Cross-table check** | A check that reads more than one table, such as a foreign key.                                                                                                                                                                     |

## Connecting to data

| Term                   | Meaning                                                                                                                                                                                 |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Data source**        | Where a table lives: a DataFrame, a Spark session or a database.                                                                                                                        |
| **Adapter**            | The object vowl uses to run queries on one data source, such as `IbisAdapter`. `validate_data` makes one for you when you pass `df=`. See [Connecting to Your Data](usage-patterns.md). |
| **Multi-source run**   | A run where schemas are on different data sources, set up with `adapters={"schema_name": adapter, ...}`.                                                                                |
| **Copied into memory** | What vowl does with the tables of a cross-table check that spans data sources. It copies each table to your machine and runs the check in DuckDB there.                                 |
| **Filter conditions**  | Rules that limit which rows vowl checks, such as only the last seven days. See [Filter Conditions](usage-patterns.md#filter-conditions).                                                |

## Results

| Term                  | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Status**            | Each check ends as `PASSED`, `FAILED` or `ERROR`. `ERROR` means the check could not run, for example because of a typo in its SQL.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Check pass rate**   | Passed checks divided by all checks. Shown as **Checks Pass Rate** in the summary.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Failed check**      | A check with the status `FAILED`, because its scalar count broke its limit. If it is a row-level check, its failed rows can go into the row counts. See [Failed checks](design-considerations/checks/check-results.md#failed-checks).                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Scalar query**      | The query that returns a check's scalar count. Every check that runs has one. See [Scalar and row queries](design-considerations/checks/check-results.md#two-queries-from-one).                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Row query**         | The query that lists the rows behind the scalar count. They are rows of the source table only when the query is a plain filter of that table. A check that returns an average, a sum, a minimum or a maximum has none. See [Scalar and row queries](design-considerations/checks/check-results.md#two-queries-from-one).                                                                                                                                                                                                                                                                                                                           |
| **Query output**      | What a check's own queries return: its scalar count and its failed rows. See [What a check gives you](design-considerations/checks/check-results.md#failed-row-results).                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Failed rows**       | The rows a check's row query returned. They are what `show_failed_rows()`, `get_output_dfs()` and residues show. Part of the query output.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Scalar count**      | The number a check's scalar query returned, which decides pass or fail. It is `actual` in the summary, `failed_rows_count` (failed checks only, `0` for a passed check), the `scalar_count` column of `get_dq_metrics_df(by="check")` and the check-level DQ metrics. Part of the query output. Under `DISTINCT` or a join it can differ from the attributed rows, and under `COUNT(DISTINCT x)` it counts values.                                                                                                                                                                                                                                 |
| **Attributed rows**   | The rows of the source table that a check's failed rows are attributed to, every copy counted. They are the `attributed_rows` column of `get_dq_metrics_df(by="check")`, the rows the annotated output flags, and the basis of the dimension, schema and run row counts.                                                                                                                                                                                                                                                                                                                                                                           |
| **Row-level check**   | A check whose failed rows can go into the row counts. It points at rows, its operator sets an upper limit such as `mustBe: 0`, and it did not end in `ERROR`. It can have passed or failed. Checks that return one number, such as an average, are not row-level. A row-level check is either attributable or not attributable. See [Check result types](design-considerations/checks/check-results.md#counted-checks).                                                                                                                                                                                                                            |
| **Row counts**        | How many rows of a table failed at least one row-level check, and how many passed them all. A row that fails two checks counts once. They are the `failed_rows` and `passed_rows` columns of `get_dq_metrics_df()`, per schema and per dimension. Only attributed rows of failed checks are in them.                                                                                                                                                                                                                                                                                                                                               |
| **Row pass rate**     | Passed rows divided by all rows. It is the `pass_rate` column of `get_dq_metrics_df()` and is in the DQ metrics. The summary does not show it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Tolerated rows**    | Failed rows of a row-level check that still passed, because its limit allows some, such as `mustBeLessThan: 10`. By default vowl does not fetch them, so they are in no output and not in the row counts, though the summary still shows the check's scalar count. [`fetch_tolerated_rows`](run-settings.md#fetch_tolerated_rows) fetches them, so they count in the row counts and appear in every output, each marked as tolerated. See [Tolerated rows](design-considerations/checks/check-results.md#tolerated-rows).                                                                                                                                                                                                                                                                              |
| **Approximate**       | The one word vowl uses for any count that may not be exact. In the summary, a sum of scalar counts across checks is approximate, because a row that fails two checks counts twice and `DISTINCT` or a join can change a count. That is **Failed Rows (approximate)** in `print_summary()` and `failed_rows_approximate` in `summary.json`. In the DQ metrics, the `approximate` column and flag is `True` when a row count could be off, for example because a row-level check ended in `ERROR` or a not-attributable check may have rows in scope. See [The approximate flag](design-considerations/checks/counting-mechanisms.md#exact-numbers). |
| **Attribute**         | To find which rows of the source table a failed row stands for, by its match key. Row counts are exact only when every row-level check is attributable. See [How Attributed Rows Work](design-considerations/checks/how-attributed-rows-work.md#counts-are-exact-only-when-attributed-to-the-source-table).                                                                                                                                                                                                                                                                                                                                        |
| **Not attributable**  | A row-level check whose failed rows vowl can't attribute to the table, so its rows are not in the row counts. Some checks are never attributable, because their failed rows have no match key, and their failed rows become residues. Others are not attributable on this run, for example because `max_failed_rows` cut their failed rows short or the table could not be exported. A not-attributable check adds nothing to the row counts, which are then marked not exact if it may have rows. `checks_not_attributable` counts them. A passed check is not attributed by default, but it is not counted as not attributable.                  |
| **Route**             | How vowl counted a check's attributed rows: `server_predicate` (the data source counts), `server_lookup` (the data source attributes the rows) or `client_lookup` (vowl attributes the rows in the downloaded table). Empty when the check is not row-level, not attributable or passed.                                                                                                                                                                                                                                                                                                                                                           |
| **Attribution query** | The query vowl runs in the data source to attribute the failed rows of a table's checks on the `server_predicate` and `server_lookup` routes. It holds the row queries of those checks, and only the numbers come back. See [Counting Mechanisms](design-considerations/checks/counting-mechanisms.md#the-four-routes).                                                                                                                                                                                                                                                                                                                            |
| **Annotate**          | To write a check's name into a row's `check_info` column.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Annotated output**  | Your full tables with a `check_info` column, plus the residues. From `get_annotated_output()`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Residue**           | The failed rows of one check that vowl could not annotate its table with. vowl makes one for a row-level check whose failed rows have no match key, for the row-level checks of a table that could not be downloaded, and for other failed checks that returned rows. Checks whose failed rows are good rows, such as a `rowCount` under `mustBeGreaterThan`, and checks that return an average, a sum, a minimum or a maximum give none. Stored under `"<schema>::<check_name>"`. See [Residues](design-considerations/checks/annotating-the-source-table.md#residues).                                                                           |
| **Summary**           | The report `print_summary()` prints, also saved as `summary.json`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **DQ metrics**        | The counts and pass rates at check, dimension, schema and run level, for dashboards. See [Understanding DQ Metrics](dq-metrics/understanding-metrics.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Run ID**            | The ID of one `validate_data` call. It ties the metrics, traces and files of one run together.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
